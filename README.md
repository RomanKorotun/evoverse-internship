# Evoverse Internship homework-4

## Завдання

Написати REST API сервер на Nest.js, який реалізує функціонал зберігпння файлів різних користувачів, а саме: має бути інтерфейс створення-огляду-видалення користувачів; кожен користувач має інтерфейс перегляду-створення-видаення файлів але лише своїх; у кожного користувача є свою окрема квота розміру файлів у сховищі, задається при створенні користувача; не користуємось базами, працюємо лише з файлами; кожен користувацький запит повинен мати в тіл поля email i password для авторизації запиту

## 1. Використані технології

### Backend

- Node.js
- Nest.js

### Frontend

- React

### База даних та зберігання

- Структура та назви бази даних описані у константах (`src/common/constants/db.constants.ts`), що дозволяє легко змінювати та налаштовувати їх під власні потреби.

#### Кастомна база даних (імітація)

- Використовується власна реалізація бази даних.
- Дані зберігаються у вигляді JSON-файлів у спеціальній директорії db.
- Кожна підпапка відповідає окремому набору даних (наприклад, користувачі, метаінформація).
- Це рішення виконує роль імітації бази даних, що дозволяє швидко тестувати та розробляти без використання зовнішньої СУБД.

#### Фізичне зберігання файлів

- Окремо від бази даних реалізовано сторейдж-сервіс.
- Файли зберігаються фізично на сервері у визначених директоріях.
- База даних містить лише метадані та інформацію про користувачів, тоді як самі файли існують як окремі об’єкти у файловій системі.

### Інфраструктура

- Docker (Dockerfile, Docker Compose)

### Dev Containers

- Використовується підтримка **Dev Containers** у VS Code.
- Для роботи потрібно встановити офіційне розширення **Dev Containers**.
- Це дозволяє підключатися безпосередньо до працюючого контейнера та розробляти всередині нього.

- Після цього відкриється середовище розробки всередині контейнера, з доступом до всіх залежностей та інструментів.

## 3. BACKEND

3.1. Щоб зайти в контейнер і виконувати команди всередині нього, використовуйте команду нижче. Тут node_app_hw_4 — назва контейнера з docker-compose.yml.

```bash

```

3.2. Логи завантаження файлів. При завантаженні великих файлів система розбиває їх на чанки (частини).  
У контейнері можна побачити debug‑логи, які показують прогрес завантаження:

```bash
[Nest] ... DEBUG [FileStorage] [UPLOAD] file=5877812-hd_720_1280_30fps.mp4 chunk=#28 23.8KB uploaded=1.59MB
```

Це дозволяє відстежувати процес завантаження та перевіряти коректність роботи chunked upload.

3.2. API маршрути

- `POST /users/signup` — реєстрація користувача
- `GET /users` — отримання списку всіх користувачів
- `GET /users/profile` — отримання одного користувача
- `PATCH /users/quota` - зміна квоти користувача

- `DELETE /accounts/remove` - видалення акаунта користувача разом із його файлами та очищає сховище

- `POST /files` — завантажити файл для поточного користувача
- `GET /files` - отримати список файлів поточного користувача
- `DELETE /files/:id` - видалити файл поточного користувача
- `GET /files/:id/:userId/view` - перегляд конкретного файла користувача
- `GET /files/:id/download` - завантажити файл поточного користувача
- `GET /files/storage/summary` - отримати інформацію про файлове сховище користувача

3.3. API відповіді

Усі значення розміру (sizeBytes, totalSizeBytes, quotaBytes) повертаються у байтах.
